LESSON 1

What Claude Code does when you ask it something

Before mods make sense, it helps to see the loop Claude Code runs every time you type something. You write a prompt. Claude reads it, along with some standing instructions, and decides what to do. Often it needs to look at a file or run a command first, so it asks Claude Code to use a tool. Claude Code runs the tool, sometimes after asking your permission, and hands the result back. Claude may use several tools in a row before it writes its answer.

prompt
What you type in the box at the bottom of Claude Code.
model
The AI itself (Claude). It reads text and writes text, and it can ask for tools to be used. It can't touch your computer on its own.
tool
Something Claude Code can do on the model's behalf: run a shell command (the Bash tool), read a file, edit a file, search the web. Asking for one is a tool call.
system prompt
Standing instructions Claude reads before your prompt, every time. You don't see them, but they shape how it behaves.
LESSON 2

So what is a mod?

A mod is a small program you add to Claude Code that gets a say at particular moments in that loop. It works like a mod for a video game, or a browser extension: you install it, and the program you already use starts behaving a little differently.

The moments a mod can step in at are called events. "You just submitted a prompt" is an event. So are "Claude is about to run a tool" and "the turn just finished". A mod says which events it cares about. For each one it gives Claude Code a function, called a hook, to run when that event happens.

mod
A small program, written in TypeScript or JavaScript, that changes how Claude Code behaves or looks. Mods arrived in Claude Code version 2.1.287, on 1 October 2026.
plugin
The package a mod comes in: a folder with a few files. A plugin can also carry other things, such as skills or agents. One with a mod inside is what this page is about.
event
A named moment in Claude Code's work, like prompt.submit or tool.call. The name is the thing, then what happened to it.
hook
The function a mod hands over for one event. Claude Code calls it each time that event happens.
TypeScript
JavaScript with type labels added, so mistakes show up before the code runs. Mods can be written in either.
LESSON 3

The three things a hook can do

Picture each event as a letter being passed down a line of desks. Your hook is one desk. It's handed the letter and a way to pass it on. That's all a hook gets, so there are only three things it can do with it.

1 · Pass it on

return next(e). The hook watched, maybe counted something, and let Claude Code carry on.

2 · Change it

return next({ ...e, command: e.command.trim() }). The rest of Claude Code sees your version, here with extra spaces removed.

3 · Stop it

return { deny: 'not on this machine' }. The tool never runs, and Claude reads your reason as the result.

e
Short for "event": the details of what's happening, such as which tool and which command. A hook can read it but not edit it in place; to change it, it makes a copy.
next(e)
The "pass it on" function. It lets Claude Code (and any other mods) do their part, then gives back the result.
{ ...e, x }
JavaScript for "a copy of e, with x changed". That's how a hook changes an event.
LESSON 4

A first mod, line by line

This mod counts how many tools Claude has used and shows the count at the bottom of the screen. It's the smallest useful mod there is, and it's real: it passes Claude Code's own checks and its test.

A mod is a folder with three files. The first two are short labels; the third is the code.

tool-counter/
  .claude-plugin/plugin.json   name, version, one-line description
  hooks/hooks.json             which file holds the code
  hooks/register.ts            the code
import type { Register } from 'claude-code'1

export const register: Register = on => {2
  let count = 03

  on('tool.call', ($, e, next) => {4
    count += 1
    $.ui.status(`Tool calls so far: ${count}`)5
    return next(e)6
  })
}

  1. Borrows the type label Register from Claude Code, so your editor can check your work. It has no effect when the mod runs.

  2. Every mod exports one function named register. Claude Code calls it once when it loads the mod, and passes in on, the function you use to sign up for events.

  3. A plain variable to hold the count. Lesson 6 explains why this one resets when the mod reloads, and what to use instead when that matters.

  4. Signs up for the tool.call event. The hook gets three things, which every hook gets: $, e and next.

  5. Uses $ to show text in the status line, the strip at the bottom of the screen.

  6. Passes the tool call on unchanged, so Claude Code runs it as normal. Leave this line out and no tool would ever run.

$
The mod's toolbox: everything it can do outside its own code goes through it. $.ui draws on screen, $.fs reads and writes files, $.store saves data. A mod's code runs in a separate space with no direct access to your computer, so $ is its only way out.
status line
The single line of text along the bottom of Claude Code's screen.
export
Makes something in a file visible to the program loading it. Claude Code looks for the exported register.

Before, during and after

Claude Code has 46 events, but a handful cover most of what people build. Here they are in the order they happen, with something you might use each one for. The colors match the full Anatomy page.

LESSON 6

How a mod remembers things

Mods often need to remember something: a count, a setting, a list. Where a mod keeps a value decides how long the value lasts. Think of three places to write things down.

reload
Claude Code throws away the mod's running copy and starts it fresh, usually because its files changed. register runs again.
$.state
Values Claude Code holds for the mod during a session. Anything drawn from them redraws by itself when they change.
$.store
A small save file of the mod's own, in a format called JSON. It survives quitting and restarting.
/clear
The command that starts a fresh conversation without quitting. It also wipes the whiteboard, and /resume and /branch do the same.

A common slip: copying the notebook onto the whiteboard at the start, then saving the whiteboard back to the notebook later. After a /clear the whiteboard is blank, and the next save overwrites the notebook with nothing. Always save from what the notebook holds. The Anatomy page shows the fix.

LESSON 7

Showing things on screen

Mods can add to Claude Code's screen, from one line of text up to a whole side panel. Today this shows up in the terminal and in the Code tab of the Claude Desktop app. Elsewhere, such as the VS Code chat panel, the mod's hooks still run but nothing it draws appears.

toast
A short message that pops up and then goes away on its own, like a phone notification.
pane
A panel the mod opens beside the conversation. With buttons in it, it can act like a small dialog.
surface
Where Claude Code is being shown: the terminal, the Desktop app, VS Code or the phone app. A mod can check which one it's on.
LESSON 8

When several mods are installed

If three mods all hook tool.call, they line up and the event is passed down the line, one desk after another. Each mod's next hands the event to the next mod, and the last one hands it to Claude Code. The order is fixed, and it's set by who's in charge.

LESSON 9

Is it safe?

A mod runs with the same permissions you have. Through $ it can read and write your files, run programs and send data over the internet. It isn't sandboxed, meaning nothing walls it off from the rest of your computer. Treat installing a mod like installing any other program.

sandbox
A locked room for code, where it can't reach the rest of your computer. Mods don't run in one.
fail open
When something breaks, it gets out of the way instead of blocking. A mod's hook that crashes, or takes more than 10 seconds, is skipped. So a mod meant to block dangerous commands lets them through if it breaks.

Before you install someone else's mod:

  • Read its code. Most mods are short.
  • Run claude plugin validate <folder>. It lists every event the mod hooks and everything it calls, so you can see that a mod sends data over the network, for example, before you run it.
  • Try it for one session first with claude --plugin-dir <folder>, which loads it without installing it.
  • Know what it can approve. Besides blocking, a mod can say yes to a tool call that would normally stop and ask you, so a mod that hooks tool.check deserves a careful read.
  • Check what a guard really covers. When you name a file with @ in your prompt, Claude Code reads it without a tool call, so a mod that keeps Claude away from secret files has to hook prompt.mention as well as tool.call.
LESSON 10

Try it yourself

The tool counter from Lesson 4 is in ~/Projects/claude-mods/samples/ours/tool-counter/. To try it in a terminal:

  1. Check it: claude plugin validate ~/Projects/claude-mods/samples/ours/tool-counter. It should say Validation passed and list tool.call and $.ui.status.

  2. Run its test: claude plugin test ~/Projects/claude-mods/samples/ours/tool-counter. It should report 1 pass.

  3. Load it for one session: claude --plugin-dir ~/Projects/claude-mods/samples/ours/tool-counter, then ask Claude to list the files in a folder. Watch the status line.

  4. Change it: edit the text in register.ts and save. In that session Claude Code reloads the mod straight away, and the count starts over at zero (the sticky note from Lesson 6).

The easiest way to write a new one is to describe it to Claude in Claude Code, for example "make a mod that shows how long each turn took". Claude writes the files, and Claude Code offers to load them into your session as soon as they're saved.
